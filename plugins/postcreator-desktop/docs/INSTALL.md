# Установка и проверка локального модуля

Используйте имеющийся Node24+. Из отдельного распакованного desktop-пакета:

```sh
node runtime/src/cli.mjs doctor
node runtime/src/cli.mjs setup --install-root /новый/постоянный/каталог --register codex
```

В общем архиве путь начинается с `plugins/postcreator-desktop/`. На Windows путь с пробелами берётся в кавычки. Для полного пути Node в PowerShell используется `&`.

## Подключение к клиенту

`setup --register codex` или `setup --register claude` находит действующий CLI и добавляет отсутствующий сервер с абсолютными путями. Уже существующие, конфликтующие и отключённые подключения сохраняются. Ошибка чтения конфигурации не считается отсутствующим сервером.

Печатный результат сообщает установленный каталог и файлы `codex.toml`/`claude.json`. Если CLI не найден, конфигурацию можно подключить через поддержанный интерфейс клиента. Отдельная команда `register --client codex|claude` работает из уже установленного модуля.

Claude также может запускать сервер из манифеста плагина через `bootstrap.mjs`; это отдельный альтернативный маршрут. Выбирайте одну активную регистрацию локального сервера. Codex использует скиллы плагина и абсолютную регистрацию своей машины.

Установка отвергает существующий целевой каталог. Для обновления выбирайте новый, проверяйте его и затем явно обновляйте нужное подключение. Прочие регистрации и предпочтения пользователя сохраняются.

## Пути и каталог результатов

`POSTCREATOR_OUTPUT_ROOT` задаёт каталог результатов задачи. Выходной путь должен оставаться внутри него, использовать новое имя и не проходить через ссылки/перенаправленные папки. Перед поздним сохранением программа повторно проверяет наличие файла. Полная атомарная защита от любых сторонних процессов не обещается.

Для режима чтения задайте `POSTCREATOR_DESKTOP_READONLY=1`. Доступны чтение сцены/материала/проекта/таймлайна и проверка состояния; правки отвергаются.

Необязательные пути: `POSTCREATOR_NODE`, `POSTCREATOR_BLENDER`, `POSTCREATOR_AFTER_EFFECTS`, `POSTCREATOR_PHOTOSHOP`, `POSTCREATOR_ILLUSTRATOR`, `POSTCREATOR_PREMIERE`, `POSTCREATOR_TOUCHDESIGNER`, `POSTCREATOR_RESOLVE`, `POSTCREATOR_RESOLVE_MODULE`, `POSTCREATOR_PYTHON`. Идентификаторы переменных сохраняются на английском. Обычные пути определяются по установленным приложениям этой машины.

## After Effects

По умолчанию используется оригинальный закрытый обработчик через штатный `AfterFX.exe -r` на Windows и через Apple Event `DoScriptFile` на macOS. Нужны исправный модуль скриптов и разрешение записи квитанции: в After Effects включите «Разрешить скриптам записывать файлы и получать доступ к сети» (Настройки → Скрипты и выражения). Если она выключена, запрос уходит в программу, но квитанция не появляется, и вы получите `ae_execution_uncertain`. На macOS при первом обращении система может спросить разрешение «Автоматизация» для программы, из которой запущен ассистент. Модуль не меняет настройки программы автоматически. Проект проверяется по идентификатору экземпляра, файлу и версии; для кадра используются актуальный `context` и `compId`.

Для дополнительной панели нужен подписанный пакет и поддержанный установщик Adobe. Выберите `POSTCREATOR_AE_TRANSPORT=panel` и файл сопряжения. Существующий сторонний мост подключается только явным `POSTCREATOR_AE_TRANSPORT=legacy` и `POSTCREATOR_AE_PACKAGE`; закрытые инструкции поставщика не загружаются.

## Photoshop и Premiere

Photoshop и Illustrator по умолчанию используют оригинальный Windows Script Host COM на Windows и Apple Events на macOS (системные настройки → Конфиденциальность и безопасность → Автоматизация). Версия определяется ответом настоящего приложения и может отличаться от найденного. На macOS подхватывается самая новая установленная версия в `/Applications`. Photoshop на macOS отдаёт PNG через «Сохранить для Web», а сохранение PSD из скрипта отклоняется: Photoshop зависает при таком сохранении. PSD сохраняйте вручную. Панель выбирается явно: `POSTCREATOR_PS_TRANSPORT=panel`.

`setup --after-effects --photoshop --premiere` создаёт отдельные приватные файлы сопряжения. Их токены не пересылаются коллегам. Генерация этих файлов сама не устанавливает/открывает панель и не меняет маршрут на панель. Для Premiere нужны подписанная панель, сопряжение, выбранный проект и подходящий `.epr` экспорта.

## TouchDesigner

`setup --touchdesigner` создаёт приватный файл и `touchdesigner-bootstrap.txt`. Выполните напечатанную команду в Python Textport явно выбранного проекта. Сервер слушает loopback и работает только со своим компонентом. Приложение и лицензия устанавливаются отдельно. `workspace.export` сохраняет новый `.tox` внутри разрешённого каталога; открытый `.toe` не сохраняется.

## Диагностика и восстановление

```sh
node runtime/src/cli.mjs doctor --app blender --live
node runtime/src/cli.mjs config --format toml
```

Запросите в ассистенте `pc_desktop_status`, затем `pc_desktop_catalog`. Команда CLI `call` создаёт отдельную диагностическую сессию; для последовательности Blender-операций нужен один MCP-сеанс.

При `ae_execution_uncertain` или `native_execution_uncertain` сохраните requestId и проверьте исходную операцию. После отправки в редактор запрос не повторяется автоматически. Восстановление квитанции предшествует новой операции; проверка экспорта дополнительно проверяет настоящий файл. Перезапуск сессии может потерять её квитанции, поэтому исходные ID и путь результата сохраняются.
