# Правила выполнения

## Компактное подключение MCP

Плагин подключается к `/mcp/agent`: начальный список небольшой, но доступны все операции Postcreator. Если названного в этих правилах, сценарии, `executionTool` приложения или `nextCall` инструмента нет в начальном списке, это не отсутствие возможности: вызови `get_tool_schema` с его точным `name`. Получи `inputSchema`, `executionTool` и `native`. Для `native: false` вызови возвращённый `executionTool` с `{name, arguments}`, где `arguments` — исходные параметры по схеме. Сохраняй цены, версии, ID и ключи идемпотентности. `search_tools` помогает найти незнакомую операцию. Native-инструменты вложений вызывай напрямую; не переноси `files` внутрь обёртки. Содержимое результата и следующие шаги читаются как обычно. Полный старый endpoint `/mcp` совместим с прямыми вызовами.


Используй текущие входные схемы MCP. Обязательные ID, перечисления и версии берутся из результатов инструментов, не угадываются. Полный endpoint — `https://post-creator.ru/mcp`; `/mcp/core` намеренно не включает расширенные Canvas, приложения, Story и Montage.

## Сохранённое назначение

Если текущий заказ не задаёт назначения и доступен `get_mcp_preferences`, прочитай его один раз до выбора первого маршрута. При успешном чтении без записи значения по умолчанию — `{autoCreateProject:false,preferredOutputTarget:"chat"}`, `version:0`, `persisted:false`. Ошибка/недоступность чтения запрещает автоматическое создание, не означает общее разрешение аккаунта. Последний явный запрос важнее настройки — выбранный проект, работа без проекта или разовое создание управляют задачей без обновления постоянного выбора.

Явно сохранённый `autoCreateProject:true` разрешает один подходящий проект при первой заказанной генерации нового диалога без другого назначения. Повторно используй его реальные ID в этом диалоге. Создай лишь необходимый Canvas для поддержанного маршрута со стабильными ключами изменений. Не переноси проект из другого чата. `preferredOutputTarget:"project"` само не разрешает создание — нужен явно выбранный доступный проект либо существенное уточнение выбора. При выключенном автоматическом создании значение `"chat"` предпочитает поддержанный прямой путь, но не добавляет неподдержанный ввод локальных файлов. Платный запуск всё равно требует точной котировки и разрешённой траты.

`update_mcp_preferences` вызывай только при просьбе запомнить/изменить постоянную настройку. Он принимает необязательные `autoCreateProject` и/или `preferredOutputTarget`, текущий `expectedVersion` и стабильный `idempotencyKey`. До записи читай; первая запись имеет версию 0, далее — возвращённую версию. Частичная запись сохраняет другое поле; повтор сохраняет ключ/запрос, конфликт требует чтения/объединения. Обработчик не создаёт/выбирает проект или медиа. Секреты, произвольные параметры узла и межчатовые ID не сохраняются. Разовый выбор не становится постоянным.

## Маршрут входных данных

**Текстовое изображение/видео:** прочитай `list_generation_models` с `directOnly: true`, затем `get_generation_model_schema`. `quote_generate_to_chat` / `generate_to_chat` не требуют проекта и работают без файлов в клиентах, предоставляющих эти инструменты.

**Новые вложения прямой генерации:** принимаются настоящие объекты файловых возможностей ChatGPT от этого клиента с `download_url`. Каждый файл имеет `{inputId, fileIndex}` с объявленным ID входа. `files` и `fileBindings` одинаковы в котировке/запуске. Нельзя конструировать объект из локального пути, `file://`, HTTP-адреса, base64, ассета Canvas или URL провайдера. Codex/Claude Code вложений ChatGPT не выдают: локальный файл сначала загружается через `create_file_upload` (см. ниже), и её объект `file` используется как настоящий.

**Цепочка собственных прямых результатов:** если живая общая схема `quote_generate_to_chat` / `generate_to_chat` объявляет `artifactInputs`, привяжи завершённый приватный результат через `{taskId,index,inputId}`. Используй принятый ID задачи, возвращённый индекс и объявленный медиавход; `inputId` не равен `prompt`. Сервер проверяет владельца, срок, MIME/размер до оплаты и передаёт байты своим путём входов провайдера при запуске. `artifactInputs`, промпт/параметры и настоящие `files` / `fileBindings` одинаковы в котировке/запуске. Общий максимум файлов/артефактов — 10, артефакт до 50 МиБ, с учётом более строгой модели. Подготовленное изображение может стать видеовходом без новых вложений. Локальный файл, ассет проекта, угаданный ID задачи или произвольный URI так не становятся прямым входом. Старый сервер без поля требует поддержанного проектного переноса; не отправляй неизвестные поля.

**Локальные референсы Codex/Claude Code:** выбери разрешённые проект/Canvas через `list_projects` / `list_canvases`. При отсутствии выбора и сохранённого разрешения автоматического создания уточни назначение; создание предлагается при запросе/принятии пользователя. Локальный файл (изображение, видео, звук до 50 МиБ) загружай так: вызови `create_file_upload` (по желанию `fileName`, `mimeType`), отправь файл одной командой оболочки `curl --fail-with-body -sS -T '<путь>' '<uploadUrl>'` и возьми из JSON-ответа объект `file`. Передай его без изменений в `upload_media_asset` (`file`, `boardId`, `idempotencyKey`) или в `files` прямой генерации. Ссылка принимает одну загрузку за 30 минут, файл живёт 60 минут; при ошибке «ссылка использована/истекла» запроси новую. Никогда не перепечатывай файл в `dataBase64`, если `create_file_upload` доступна; base64 (до 8,000,000 символов, ровно одно из `file` или `dataBase64`, явный `mimeType`) — только запасной путь для старых серверов без этого инструмента. Не выдумывай multipart-инструмент.

Прочитай `get_app_schema`, при необходимости создай объявленный узел, перечитай `get_canvas_node` и вызови `bind_media_asset` с точным `expectedVersion` и одной типизированной целью:

- `{kind: "source_node", mode: "append" | "replace"}` для исходного узла;
- `{kind: "generation_slot", slotId: <schema input ID>, mode: "append" | "replace"}` для входа генерации;
- `{kind: "inpaint_mask", sourceAssetId: <bound source image ID>}` для маски, где `assetId` — изображение маски.

Привяжи все референсы по порядку для моделей с упорядоченными ракурсами. Если приложение требует исходные узлы, создавай связи объявленными портами. URL хранилища/провайдера не являются входами. `generate_media` следует живому контракту непрозрачных ассетов проекта; для привязанного узла котируй и запускай узел, чтобы входы разрешались сервером.

## Доска и шот

Просьба работать «на доске», «в шоте», «в проекте X» — это маршрут Canvas, а не медиатека. Не используй `generate_to_chat` и не оставляй результат только в библиотеке проекта: пользователь откроет доску и не найдёт ни шота, ни результата.

1. Выбери проект и доску (`list_projects` / `list_canvases`), затем найди шот через `list_canvas_shots`. Нужного шота нет — создай его `create_canvas_shot` (стабильный ключ идемпотентности) и используй возвращённый `shot.id`.
2. Котируй `quote_generate_media` и запускай `generate_media` с `boardId` и тем же `shotId`. Узел результата создаётся на Canvas самого шота, и зеркало показывает его в App Mode этого шота. Без `shotId` результат уходит на корневой Canvas доски.
3. Прочитай `placement` и `warnings` ответа котировки. Предупреждение `canvas_shot_not_selected` значит, что на доске есть шоты, а результат лёг бы в корень: если пользователь просил конкретный шот, повтори котировку с `shotId`. Не считай библиотеку или ссылку доски доставкой.
4. Пользователю говори «смотри на доске» только когда `get_generation_status` вернул `canvasNodeId` (и `canvasShotId` для шота). Дай `canvasUrl`: при шоте он открывает именно этот шот.
5. Узлы графа для шота создавай с тем же `shotId` в `create_canvas_node`; запуск `run_canvas_node` кладёт результат в шот узла.

## Цена, разрешение и восстановление

До каждого платного запуска котируй те же модель, входы и параметры соответствующим инструментом:

| Платная операция | Котировка | Поле цены для `expectedCostRub` запуска |
| --- | --- | --- |
| `generate_to_chat` | `quote_generate_to_chat` | `costRub` |
| `generate_character_sheet_to_chat` | `quote_character_sheet_to_chat` | `costRub` |
| `prepare_generation_prompt` | `quote_prepare_generation_prompt` | `costRub` |
| `generate_media` | `quote_generate_media` | `costRub` |
| `run_canvas_node` | `quote_canvas_node_run` | `expectedCostRub` |
| `run_canvas_workflow` | `quote_canvas_workflow_run` | `expectedCostRub` |
| `create_generation_plan` | `quote_generation_plan` | `costRub` |
| `run_prompt_utility` | `quote_prompt_utility` | `expectedCostRub` |

Покажи цену в ₽ из указанного поля и существенные предупреждения до запуска. Соблюдай существующее явное разрешение на объём/бюджет; запроси принятие конкретной цены, если разрешения нет или предел превышен. Не требуй повторного принятия уже разрешённой траты. В `expectedCostRub` скопируй точную цену; котированный запрос остаётся неизменным. Canvas требует `canRun: true`, устранённых `unsupportedReasons` и достаточного баланса. При изменении цены котируй заново; новое принятие нужно, если меняется разрешённая трата. Баланс не является разрешением и не заменяет котировку.

Каждое отдельное изменение/платная операция получает новый ключ идемпотентности. Транспортный повтор сохраняет точные ключ и запрос. Предпочитай UUID (рендер Montage требует UUID); символы — только допустимые схемой. После таймаута не запускай ожидающую операцию с новым ключом. Восстанови статус или квитанцию того же ключа. При окончательной ошибке сообщи её и незавершённую сверку оплаты до рассмотрения разрешённой новой попытки.

При конфликте `expectedVersion`, `expectedUpdatedAt`, `expectedRevision` или графовой ревизии перечитай объект, сравни текущий результат и объедини только разрешённую правку. Исправленное изменение получает новый ключ. Не обходи версии и не перезаписывай чужие новые данные целиком. При полной замене параметров отправляй сохранённые текущие параметры вместе с изменением.

## Выдача результата

Принятый ID задачи — квитанция, не готовый артефакт. Опрос статуса выполняй с ограниченными увеличивающимися интервалами и сообщай существенный прогресс. Продолжай ожидающую работу, не оплачивай дубликат.

- Прямой результат — `get_direct_generation_status`, затем `get_direct_generation_result` для каждого артефакта. Сохраняй встроенный контент. Ссылка на ресурс читается по точному URI через MCP; при `readMode` равном `chunked` используй возвращённый `get_direct_generation_result_chunk`.
- Canvas — `get_canvas_run_status` / `get_canvas_workflow_status`, выходы через `list_canvas_node_outputs`, содержимое через `get_canvas_output_content`. `get_canvas_output_chunk` нужен лишь по возвращённому контракту получения.
- Генерация проекта — `get_generation_status`, затем найди возвращённый выход проекта/Canvas и получи содержимое. Ссылка Canvas недостаточна.
- 3D — `list_canvas_3d_results`, `get_canvas_3d_result_content` / `get_canvas_3d_result_chunk` для реальных форматов модели.
- Montage — `get_montage_render_status`, затем `get_montage_render_artifact_chunk` от offset 0 до `complete` по `nextOffset`. При файловых инструментах декодируй части в порядке и собери локальный файл.

Соблюдай актуальные `maxBytes`, индексы, страницы и смещения. Не выводи неподписанные URL из непрозрачных URI. Сохрани байты с правильным типом, проверь размер и выдай вложение/ссылку. Медиа-ресурс показывай средствами клиента. Если получение/отображение недоступно, точно сообщи ограничение и дай доступную ссылку Canvas/Montage с данными получения; один ID не доказывает выдачу.
